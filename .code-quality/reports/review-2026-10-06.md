# Code review — незакоммиченные изменения (2026-10-06)

Scope: всё, что не закоммичено на `main` после `279f7a1`. Это 16 изменённых файлов, а также новые `src/sandbox/`, `src/core/TextureManager.js`, `scripts/` и `assets/`. Стек: vanilla ES modules + PixiJS v8 через CDN importmap. Сборки, `package.json` и линтера нет.

## Verdict

Не мержить как есть. Есть один краш и две ошибки, которые увидят игроки:

1. После game over нажатие **R** роняет игровой цикл. Причина: DevSandbox держит ссылку на `Graphics`, который `clearWorld()` уже уничтожил.
2. Dev-панель с читами и отладочными оверлеями открыта у **всех** игроков в проде.
3. Если закрыть финальный диалог клавишей Enter, экран победы пропускается и сразу стартует endless.

Каждое исправление — 2–5 строк. Остальное — поддерживаемость: дублирование в `GameplayScene`, god-class в `DevSandbox` на 2,9k строк, мёртвые читы.

### [CRITICAL] Restart после game over роняет игровой цикл — `src/sandbox/DevSandbox.js:2844`, `src/scenes/GameplayScene.js:129`

Как это происходит:
1. `renderDebugOverlays` добавляет `this.debugGfx` в `scene.actors`.
2. `clearWorld()` (её вызывает `startGame` по R/Enter после смерти) делает `actors.removeChildren().forEach(c => c.destroy(...))` и уничтожает `debugGfx` вместе со всем остальным.
3. На следующем тике `debugGfx.parent !== scene.actors`. Уничтоженный объект снова добавляется в сцену, и на нём вызывается `.clear()`. В Pixi v8 у уничтоженного `Graphics` поле `_context === null`, поэтому вылетает TypeError внутри ticker-коллбэка.
4. Тикер больше не планирует кадр, игра замирает, появляется красный оверлей из `index.html`.

Путь подтверждён чтением кода. В браузере не воспроизводилось — проверь: умереть, нажать R.

**Fix:**
```js
// before
if (this.debugGfx.parent !== scene.actors) {
  scene.actors.addChild(this.debugGfx);
}
// after
if (!this.debugGfx || this.debugGfx.destroyed) {
  this.debugGfx = new Graphics();
  this.debugGfx.zIndex = 999999;
}
if (this.debugGfx.parent !== scene.actors) scene.actors.addChild(this.debugGfx);
```

### [HIGH] Enter на последней реплике финала пропускает экран победы — `src/scenes/GameplayScene.js:1196-1212`

В одном кадре происходит следующее:
1. `dialogue.advance()` вызывает `onDone`, затем `showVictory()`, и `mode` становится `"victory"`.
2. Ниже в том же `update()` проверка `mode === "victory" && isPressed("Enter")` видит тот же самый `justPressed` и сразу вызывает `startEndless()`.

Игрок с Enter (а Enter — одна из клавиш продвижения диалога) никогда не увидит победный оверлей.

**Fix:** отдать кадр, в котором закрылся диалог, без обработки остальных режимов.
```js
if (this.game.mode === "dialogue") {
  this.dialogue.update(dt);
  if (this.app.input.isPressed("Space", "Enter", "KeyJ", "KeyZ", "KeyK")) {
    this.dialogue.advance();
    if (this.game.mode !== "dialogue") return;
  }
}
```
Если `return` слишком грубо для HUD и камеры, введи флаг `inputConsumed`. Как вариант — добавь `InputManager.consume(...codes)`, который удаляет коды из `justPressed`.

### [MEDIUM] Despawn-логика скопирована 8 раз — `src/scenes/GameplayScene.js`

Шаблон «уничтожить view → удалить из Map → `splice` из массива» повторяется в:
- `removeEnemy:401`, `removeCrate:448`, `removePickup:490`;
- `clearAllCrates:461`, `clearAllPickups:503`;
- `updateBullets:750`, `updatePickups:1107`, `hitCrate:885`, cleanup-цикле `:1399`.

`clearAll*` при этом не переиспользуют `remove*`. Спавн (`spawnCrates`, `spawnCustomCrate`, `spawnPickup`, `spawnCustomPickup`) дублируется так же.

```js
despawn(list, views, model) {
  const view = views.get(model);
  if (view) { view.destroy({ children: true, texture: false }); views.delete(model); }
  const i = list.indexOf(model);
  if (i !== -1) list.splice(i, 1);
}
```

Попутно это закрывает `hitCrate:892`: там `splice(indexOf(c), 1)` без проверки на `-1`, и если `c` нет в списке, удаляется **последний** ящик.
